# Troubleshooting

Read `errors[].code` and `errors[].message` from `grv --json ...` output.

| Symptom                                                      | Likely cause and fix                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NOT_FOUND`: "adapter is not installed"                      | Run `grv adapter list`. Homebrew on Apple silicon installs DuckDB and Salesforce adapters automatically. Otherwise install with `grv adapter install <path>`, or set `GRV_ADAPTERS_DIR` to the directory holding installed adapters. Note that `GRV_ADAPTERS_DIR` hides the Homebrew adapters. |
| Error mentioning a protected directory, owner or permissions | Adapter directories (and all their parents) must be owned by the user or root, not group/other-writable, and contain no symlinks. Ask the user to move the adapters or fix ownership; do not `chmod 777` or symlink.                                                                           |
| `INVALID_DECLARATION`                                        | Field, type or name is wrong. Compare against `declarations.md`. Common causes: unquoted `decimal128(...)`, unsupported type (`int32`, `float32`), unknown field, missing `columns` on a SQL pull.                                                                                             |
| `INVALID_DECLARATION` asking for an empty-source contract    | The pull selected no data and GRV cannot infer the schema. Add `expect: { columns: [...] }` to the table, or pull a revision that contains the table.                                                                                                                                          |
| `STATE_CONFLICT` on push before reading the source           | The dataset has a table this declaration does not list. Add it, drop it with `selection.drop`, or use another dataset.                                                                                                                                                                         |
| `STATE_CONFLICT` / `ENGINE_BUSY` during a transfer           | Another run holds the dataset or the DuckDB database. Wait and retry. If a run crashed, `grv recover <dataset> --grv <root> --dry-run` shows what recovery would do once the lease has expired.                                                                                                |
| `OUTCOME_UNKNOWN`                                            | GRV could not confirm whether the operation finished. Retry with the same `--attempt <uuid>` (printed on stderr at the start). Do not start a new push.                                                                                                                                        |
| `INTEGRITY_FAILURE`                                          | Stored data does not match its recorded hashes. Stop and tell the user. Run `grv verify <dataset> --grv <root> --full` to find out what is affected.                                                                                                                                           |
| Conversion error naming a column                             | The source type does not widen exactly into the declared type. Declare a wider type (e.g. `int64`, a larger `decimal128`) rather than casting in a filter.                                                                                                                                     |
| A revision disappeared after `gc --apply`                    | Only pinned or held revisions survive GC. Pin revisions you need: `grv pin <dataset> --grv <root> --revision N --reason <why>`.                                                                                                                                                                |
| S3 `AccessDenied` on multipart upload                        | The writer lacks multipart permissions. Set `GRV_S3_UPLOAD_MODE=single-put` (objects are buffered in memory, 1 GiB default limit).                                                                                                                                                             |
| Cloud downloads time out                                     | Increase `GRV_CLOUD_READ_TIMEOUT_SECONDS` (max 3600).                                                                                                                                                                                                                                          |
| Retrying a CI job cannot find the attempt                    | Push state lives in a local state directory. On ephemeral machines, put it on durable storage with `--state <dir>`, or treat each job as new work and schedule `grv recover` and `grv gc`.                                                                                                     |
