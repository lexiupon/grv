# macOS ARM64 0.1.0 initial scoped release

Target approved by user: version 0.1.0, macOS ARM64 only. Candidate local
commit/freeze and existing staging S3 writes are authorized. No external
push/tag/upload/publication destination has been approved yet.

## Candidate contents and claims

- Production grv CLI, DuckDB and Salesforce process adapters; no fixture or
  adversarial executables. Guarded DuckDB1.5.6 native library, pinned signed
  httpfs/aws extensions, Rust/GRV/upstream/third-party notices included.
- Storage v2/client v1/adapter interface v1. complete_client_v1 remains false:
  this scoped initial release is not full four-platform or full normative
  matrix qualification.
- Native DuckDB snapshot push, transactional local replacement/append pulls,
  S3 fixed-file view pulls, managed/external builds and inspection require
  candidate named gates. Source acquisition remains nonresumable; accepted
  exports/captures and immutable terminal receipts have distinct retry rules.
- Salesforce is push-only, capture-window consistency; REST-first auto.
  Nullable-text Bulk projections precisely refuse; eligible numeric/ID/date/
  bool Bulk exact pages are separately tested. No silent field removal or
  non-null empty-string/subsecond/nullable-checkbox claim.
- Local/S3/GCS backend conditional operations and representative production
  lifecycles require named authorized candidate runs. GCS views are not
  advertised: verified files materialize locally. Source-free replay must not
  authenticate/query/allocate again.
- GC/recovery is conservative when writer or remote effects are unresolved.
  Expiry/local locks are not proof that remote uploads stopped. Busy/unknown
  safety outcomes are not successful recovery/liveness claims.

third-party license/attribution/NOTICE texts with hashed payloads and documented
review. Include extras rather than infer only dynamic linkage. Exact upstream
CI/signing history and a reconstructed linked SBOM are NOT required as absolute
prerequisites. Native/extension exact dependency graph completeness is not
claimed. Known required missing license/notice text still blocks distribution.

Package/verify must validate the reviewed policy and actual notice payload
hashes separately from binary signature/hash verification. A policy change
alone does not fabricate notice files or approve an unresolved required text.
